# Зохиомжийн walkthrough (L15)

## 1. Нэг бараа орлого болж UI дээр гарах зам
Жишээ: SUP01-ээс A агуулахад P01 Дэвтэр 5 ширхэг ирэв (өмнө нь 10 байсан).

| # | Давхарга | Юу болох | Холбогдох баримт |
|---|----------|----------|-------------------|
| 1 | UI | Нярав form бөглөнө: агуулах A, нийлүүлэгч SUP01, P01 × 5 | — |
| 2 | HTTP | `POST /api/v1/documents` `{type:"receipt", warehouse_id:1, supplier_id:1, lines:[{product_id:1, quantity:5}]}` | api-contract §4 |
| 3 | Service | quantity > 0 бүхэл эсэх, ижил бараа хоёр мөр эсэх, агуулах/бараа байгаа эсэхийг шалгана. Буруу бол 422/404 | state-rules §6 |
| 4 | Repository → DB | documents (draft) + document_lines мөр үүснэ. **Үлдэгдэл 10 хэвээр** | P06 |
| 5 | HTTP | `POST /api/v1/documents/2/post` | api-contract §5 |
| 6 | Service + DB | Нэг transaction: status → posted, stock_movements +5, stock_balances 10 → 15. Алдаа гарвал бүгд rollback | state-rules §2, T04 |
| 7 | HTTP | 200 `{status:"posted"}` | |
| 8 | UI | Үлдэгдлийг дахин ачаалж (`GET /stock`, G4-д нэмнэ) P01 = 15 гэж харуулна | |

## 5. Нэмэлт кейс
**ERD: шинэ агуулах C нэмбэл юу өөрчлөгдөх вэ?** (G2 асуултад бэлтгэл)
- Schema өөрчлөгдөхгүй. `warehouses`-д нэг мөр (C) нэмэгдэнэ.
- stock_balances-д C-ийн мөрүүд анхны хөдөлгөөн батлагдах үед үүснэ. Хос UNIQUE нь C-д мөн үйлчилнэ.
- API өөрчлөгдөхгүй, `warehouse_id: 3` гэж явуулна. UI-д агуулахын сонголтод C нэмэгдэнэ.
- Хэрэв үлдэгдлийг products-д нэг багана болгосон бол энд schema өөрчлөх шаардлагатай болох байсан. Энэ нь тусдаа хүснэгтийн давуу тал.

**JS: үлдэгдэлгүй үед зарлага**
| Оролт | Хүлээсэн | Гарсан |
|-------|----------|--------|
| `[{type:"issue", qty:1}]` | алдаа | `үлдэгдэл 0 байхад 1 зарлагадах боломжгүй` ✓ |
| opening 10, issue 4, receipt 5 (дараалал өөр) | 11 | `{ ok: true, value: 11 }` ✓ |
