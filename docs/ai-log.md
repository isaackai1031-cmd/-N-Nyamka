## — L02-L04 ноорогийн шалгалт

### Би юуг шалгасан
- **AC бүрийн тоог өөрөө тооцож шалгав:** `requirements.md` дотор US-01-ээс US-08 хүртэл нийт 24 AC байгаа эсэхийг гараар тоолов. US-01: 3, US-02: 3, US-03: 3, US-04: 3, US-05: 3, US-06: 3, US-07: 3, US-08: 3 → нийт 24. Зөв.
- **`baseline.md`-ийн JS/Python кодыг өөрөө ажиллуулав:** `RICE-01 (8 ширхэг)` гэж хоёуланд нь гарсан эсэхийг шалгав. JS-д `p.qty`, Python-д `p["qty"]` гэж зөв бичигдсэн эсэхийг харьцуулав.
- **SQL JOIN-ийн таамаглалыг гараар тооцов:** `products` (MILK-01, RICE-01, EGG-01) ба `stock` (MILK-01=24, RICE-01=8) хүснэгтүүдээр INNER JOIN хийхэд EGG-01 гарахгүй, зөвхөн MILK-01, RICE-01 гарна гэж гараар тооцож, `baseline.md`-д бичсэн таамагалтай харьцуулав. Таарсан.
- **HTTP status code-ийн хэрэглээг шалгав:** `problem.md` дахь PR-01 → 409, PR-02 → 409, `requirements.md` дахь AC-01.3 → 422, AC-05.3 → 409. Аль нь 409, аль нь 422 байх ёстойг `baseline.md`-ийн "Мэдэхгүй" хэсэгт бичсэн асуулттай холбож шалгав.
- **`environment.md`-ийн хувилбаруудыг өөрийн компьютертой харьцуулав:** Node v20.11.0, Python 3.11.5, MySQL 8.4 — өөрийн орчинтой таарч байгаа эсэхийг `node -v`, `python --version`, `mysql --version` командаар шалгав.

### Юутай харьцуулж шалгах ёстой вэ
- **Гараар тооцсон үр дүн ↔ код/SQL-ийн бодит гаралт:** AC бүрийн "Дараа" баганад бичсэн утга ба тестээр гарах утгыг мөр бүрээр харьцуулна.
- **`requirements.md`-ийн AC тоо ↔ `traceability.md`-ийн мөр:** AC бүр traceability-д байгаа эсэхийг харьцуулна. Одоогоор AC-02.1, AC-02.3, AC-06.3, AC-08.2, AC-08.3 тестгүй байгааг илрүүлсэн.
- **`problem.md`-ийн PR ↔ `requirements.md`-ийн AC:** PR-01 (давхар SKU) ↔ AC-01.2, PR-02 (үлдэгдэл хүрэхгүй) ↔ AC-05.3, PR-03 (posted засах) ↔ AC-06.3, PR-04 (давхар батлалт) ↔ AC-06.2 гэж холбож шалгана.
- **ХОУ-ын хариу ↔ албан ёсны баримт:** JOIN, transaction, HTTP status-ийн ХОУ-ын тайлбарыг MDN, MySQL албан баримттай харьцуулна.
