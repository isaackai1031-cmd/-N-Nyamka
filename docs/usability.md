# Хэрэглэх байдлын шалгалт (L13)

Файл: `frontend/index.html`, `frontend/app.js`, `frontend/style.css`
Ажиллуулах: `frontend` хавтаст `python -m http.server 8000` → http://localhost:8000

## Бүтэц: төлөв → дүрслэл → үйл явдал
| Хэсэг | app.js дахь функц | Үүрэг |
|-------|-------------------|-------|
| Төлөв | `state` объект | Үнэн өгөгдөл (products, query, status) |
| Өгөгдөл өөрчлөх | `validateProduct`, `addProduct` | DOM-д хүрэхгүй. Шинэ массив үүсгэнэ |
| Дүрслэл | `render`, `showFieldErrors` | state-ээс DOM зурна. state-ийг өөрчлөхгүй |
| Үйл явдал | submit, input, click listener | Хүсэлтийг өгөгдлийн функц руу дамжуулна |

## Хүртээмж (accessibility)
- Талбар бүр `<label for>`-той. Дэлгэц уншигч талбарын нэрийг уншина.
- Алдааны текст `aria-describedby`-ээр талбартай холбогдсон, `role="alert"`. Алдаатай талбар `aria-invalid="true"` + улаан хүрээтэй.
- `:focus-visible` дээр улбар шар тод хүрээ. Keyboard-оор аль талбар дээр байгаа нь харагдана.
- Төлөвийн мөр `role="status" aria-live="polite"`. "P06 нэмэгдлээ" гэх мэтийг дэлгэц уншигч уншина.
- Хүснэгтийн гарчиг `<th scope="col">`.
- `textContent` ашигласан, `innerHTML` биш. Бараа нэрэнд `<script>` бичсэн ч код болж ажиллахгүй.

## Яагаад серверийн validation бас хэрэгтэй вэ?
Браузерийн шалгалтыг хэрэглэгч DevTools, Postman эсвэл өөр програмаар тойрч хүсэлт явуулж чадна. Мөн хоёр хэрэглэгч зэрэг ижил SKU нэмэхийг браузер мэдэхгүй. Тиймээс браузерийн шалгалт нь **хэрэглэгчид хурдан тайлбар өгөх**, серверийн шалгалт (422/409) ба DB-ийн UNIQUE нь **жинхэнэ хамгаалалт** юм.
