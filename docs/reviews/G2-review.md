## 2. Зохиомжийн дүгнэлт: G2-оос G3-д авч явах шийдвэрүүд
| Шийдвэр | Хаана | G3-д юу гэсэн үг вэ |
|---------|-------|----------------------|
| Үлдэгдэл `stock_balances`-д агуулах тус бүрээр хадгалагдана. `products`-д qty байхгүй | data-dictionary, design-review №1 | `GET /products` qty буцаахгүй |
| `id` нь дотоод түлхүүр, `sku` нь бизнесийн UNIQUE код, `name` давхардаж болно | design-review №2 | URL-д id ашиглана, SKU-гаар хайна |
| SKU-г том үсэг рүү хөрвүүлж, `^[A-Z0-9-]{2,30}$`-аар шалгана | api-contract §3 | Node-ийн validation UI-тай ижил дүрэмтэй байна |
| 409 нь төлөвийн зөрчил, 422 нь оролт өөрөө буруу | api-contract | Бизнес алдаанд 200 буцаахгүй |

## 3. Аман хамгаалалтад бэлдэх асуултууд
Хариултыг өөрийн үгээр, баримтаа нээлгүйгээр хэлж чаддаг болтлоо давтана.

1. P01 A агуулахад 10, B агуулахад 2 байна. Үүнийг ERD-д яаж хадгалах вэ? Яагаад products-д qty багана байж болохгүй вэ? (data-dictionary, шийдвэр 1)
2. `UNIQUE (warehouse_id, product_id)` байхгүй бол ямар алдаа гарах вэ?
3. Ижил баримтыг хоёр удаа батлахад юу болох вэ? Status, movement, balance гурав юу болох вэ? (state-rules, дүрэм 2–3)
4. Хоосон нэр яагаад 422, давхар SKU яагаад 409 байх вэ?
5. `fetch` 404 дээр яагаад reject хийдэггүй вэ? `response.ok`-ийг `response.json()`-оос өмнө шалгахгүй бол юу болох вэ? (http-observations)
6. Хоосон жагсаалт ба алдаа хоёрыг UI яагаад өөр харуулдаг вэ?
7. `sort()` ба `filter()` хоёрын эх массивт үзүүлэх нөлөө ямар ялгаатай вэ? (js-cases)
8. `"10" + "5"` яагаад `"105"` болдог вэ? Яагаад `Number()`-ээр хөрвүүлэхийн оронд typeof-оор татгалзсан бэ?
9. Браузерийн validation байхад серверийнх яагаад бас хэрэгтэй вэ?
10. Шинэ агуулах C нэмбэл schema, API, UI-д юу өөрчлөгдөх вэ? (design-review §5)

**Шинэ нөхцөл (багш асууж магадгүй):**
- Нэг баримтад P01-ийг 3, 2 гэж хоёр мөрөөр бичвэл юу болох вэ? → `UNIQUE (document_id, product_id)`, 422
- Барааг устгах хүсэлт ирвэл яах вэ? → soft delete (`is_active = false`), хөдөлгөөнтэй барааг устгахгүй
